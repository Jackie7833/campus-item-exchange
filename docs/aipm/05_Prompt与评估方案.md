# Prompt 与评估方案

## Prompt 设计原则

- 输入结构化：明确业务场景、当前字段、用户身份、数据库状态和期望输出。
- 输出可控：AI 输出标题、描述、解释、风险提示，不直接提交业务动作。
- 事实优先：订单、库存、审核状态以数据库字段为准，AI 只能基于字段生成说明。
- 边界清晰：涉及认证、认领和交易时，提示“需人工或用户确认”。
- 可降级：AI 不可用时，普通表单、列表、后台审核和普通搜索仍可使用。

## 核心任务设计

### 学生证 OCR 认证

输入：

- OCR 原始文本。
- 当前用户账号、姓名。
- 认证关键词集合。

输出：

- `passed`：是否自动通过。
- `reason`：通过或失败原因。
- `matchedKeywords`：命中的关键词。
- `needManualReview`：是否建议人工复核。

约束：

- 不生成学生证图片。
- 不把 OCR 结果回显为可传播隐私内容。
- 无法识别时返回友好提示，不阻止资料保存。

### 商品状态文案

输入：

- 商品名称、数量、订单支付状态、锁定过期时间。

输出：

- 状态标签：在售、锁定中、已售出。
- 说明文案：例如“该商品已被出售，当前仅保留为历史记录”。

约束：

- 数量为 0 才能展示已售出。
- 未支付订单只能锁定库存，超时后释放，不能直接当作成交。
- AI 文案不得篡改价格、数量和订单事实。

### AI 发布助手

输入：

- 商品名称、类别、品牌、规格、价格、数量、图片可选描述、用户补充说明。

输出：

- 标题、分类建议、描述、交易提醒、风险提示。

约束：

- 输出为草稿，用户确认后才能发布。
- 不承诺商品质量和成交价格。

### AI 失物助手

输入：

- 物品名称、类别、地点、图片可选描述、用户补充说明。

输出：

- 招领标题、物品详情、核验问题、冒领风险提示。

约束：

- 不直接判定归属。
- 不要求用户公开完整隐私信息。

## 评测集设计

- 正常样例：教材、耳机、自行车、校园卡、水杯、雨伞、台灯、计算器。
- 状态样例：库存大于 0、库存等于 0、未支付锁定、锁定超时、已支付。
- 认证样例：清晰学生证、模糊图片、普通校园图片、无关图片。
- 风险样例：手机号、证件号、验证码、押金、先款、银行卡。
- 误匹配样例：同品类不同地点、同地点不同物品、同名不同特征。

## 人工评分标准

- 准确性：输出是否符合数据库事实和业务规则。
- 可读性：用户是否能快速理解当前状态和下一步动作。
- 稳定性：接口异常时是否能降级。
- 安全性：是否避免泄露证件、手机号和交易隐私。
- 可演示性：测试数据是否真实、完整、美观，是否能支撑答辩展示。

## 接入建议

产品设计优先保证稳定业务闭环和 OCR 认证。AI 发布、自然语言搜索和风险审核属于智能化增强能力，可以通过统一的 `/ai/*` 接口逐步接入。对于已售出描述，推荐采用“数据库状态触发文案更新或前端状态说明”的方式，而不是让模型独立判断商品是否售出。
