# 上线、测试与复盘文档

## 上线准备

- 后端 Flask 服务正常启动，并能连接 MySQL。
- 数据库已准备完整演示数据，且支持通过初始化脚本恢复一致结果。
- 微信小程序发布版本与前端设计保持一致。
- 图片上传目录包含轮播图、失物图、二手图、新闻图和用户头像。
- 百度 OCR 配置可用；不可用时学生证认证返回友好错误。
- 前端 `base.url` 指向实际可访问后端地址。
- 若提交体验版或正式版，需要配置 HTTPS 域名和微信 request/uploadFile 合法域名。

## 上线前测试

- 微信开发者工具预览：首页、底部导航、列表、详情、个人中心均可打开。
- 登录新演示用户，例如 `student01 / 123456`。
- 验证普通用户登录不因未认证被阻止。
- 上传学生证测试图片，验证认证通过和失败两种结果。
- 二手分类点击、商品详情跳转、返回顶部、搜索均正常。
- 失物列表、详情、认领申请和评论均正常。
- 个人中心业务卡片只展示当前用户自己的发布、申请、订单和收藏数据。
- 后台管理员账号可登录，能查看和维护用户、商品、失物、新闻和订单。

## 数据回归

- 商品类型符合校园物品流转场景，例如数码设备、宿舍用品、学习资料、运动出行、其他。
- 用户账号、昵称、头像、评论和业务内容具备真实校园语境。
- 评论内容贴合商品、失物或新闻场景，能够辅助演示互动效果。
- 二手物品包含在售和已售出状态。
- 购买订单包含已支付、未支付、锁定和释放相关记录。
- 轮播、失物、二手、新闻图片均能正常加载。
- 用户头像使用生成的校园学生风格头像。

## AI 与异常测试

- OCR 正常：清晰学生证可识别，认证通过后显示认证图标。
- OCR 失败：普通图片、模糊图片或接口异常时提示失败原因。
- AI 文案：库存为 0 时展示已售出说明，不能在库存仍大于 0 时误显示。
- 服务异常：AI 或 OCR 不可用时，普通资料保存、发布和浏览不受影响。

## 真实上线后测试

- 生产冒烟：登录、浏览、发布、上传、认领、下单、评论、收藏全部跑通。
- 多账号隔离：不同用户只能在个人中心看到自己的发布、申请、订单和收藏。
- 管理员权限：后台可以看到全局数据，普通用户不能访问后台管理能力。
- 数据安全：学生证、手机号、订单信息不会被公开回显到不该出现的位置。
- 运营验证：观察认证通过率、商品发布量、订单创建量、认领申请审核量。

## 复盘框架

- 哪些页面最容易让用户理解平台价值？
- 哪些功能仍然依赖后台人工处理？
- OCR 认证的误识别和失败提示是否足够清楚？
- 个人中心是否真正减少了用户查找自己数据的成本？
- 下一版是否继续做 AI 发布助手、自然语言搜索和风险审核？
